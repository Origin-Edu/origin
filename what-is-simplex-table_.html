Chapter 2: The Foundations — From Geometry to Algebra

We saw the feasible polygon. We saw the optimal vertex.

Now we build the algebraic machinery that walks from vertex to vertex without ever drawing a graph.

The Callback: What Chapter 1 Gave Us

  • Furniture factory: tables (x₁), chairs (x₂)
  • Wood: 2x₁ + x₂ ≤ 100 | Labor: x₁ + 2x₂ ≤ 80
  • Profit: z = 5x₁ + 4x₂ (maximize)
  • Feasible region = convex polygon with 4 vertices
  • Key geometric fact: Optimum occurs at a vertex
  • Key unanswered question: How do we algebraically move from vertex to vertex?

Standard Form: Equality Constraints

Inequalities hide the algebra. We make them equalities by adding slack variables:


Wood:    2x₁ +  x₂ + s₁ = 100   (s₁ = unused wood)
Labor:   x₁ + 2x₂ + s₂ =  80   (s₂ = unused labor)

x₁, x₂, s₁, s₂ ≥ 0

s₁, s₂ ≥ 0 by definition — they measure unused resources.

We now have 4 variables, 2 equations. The geometry is unchanged; we've just made the constraints explicit.

Basic and Non-Basic Variables

  • n = 4 variables (x₁, x₂, s₁, s₂), m = 2 constraints
  • Choose n − m = 2 variables to set to zero → non-basic
  • Solve the 2 equations for the remaining 2 → basic
  • Result = basic solution
  • If all variables ≥ 0 → basic feasible solution (BFS)

Each BFS corresponds to exactly one vertex of the feasible polygon.

Each vertex corresponds to exactly one BFS (assuming non-degeneracy).

Expressing Basics in Terms of Non-Basics

At the origin: basic = {s₁, s₂}, non-basic = {x₁, x₂}


s₁ = 100 − 2x₁ − x₂
s₂ =  80 −  x₁ − 2x₂

This is Gaussian elimination — rewriting each basic variable as a function of the non-basics.

The coefficients tell us: if we increase a non-basic, how do the basics change?

This rewritten system is the tableau's soul. Every pivot is just a change of basis.

The Objective in Terms of Non-Basics

Original objective: z = 5x₁ + 4x₂

At the origin, x₁ and x₂ are non-basic (currently zero). Substitute the basic expressions… but wait — the objective already uses only non-basics!


z = 0 + 5x₁ + 4x₂

The coefficients of non-basics in the objective are the reduced costs:

  • x₁ reduced cost = +5
  • x₂ reduced cost = +4

Positive reduced cost → increasing that non-basic improves the objective.

Optimality Condition at a BFS

A BFS is optimal iff all reduced costs ≤ 0 (for maximization).

At the origin: reduced costs are +5 and +4.

Not optimal. We must move.

Choosing the Entering Variable

Most positive reduced cost enters — steepest ascent.

  • x₁ reduced cost = 5
  • x₂ reduced cost = 4
  • x₁ enters the basis

Geometric meaning: choose the edge with the fastest profit increase per unit step.

From the origin, two edges emanate: along x₁-axis (wood constraint) and x₂-axis (labor constraint).

x₁ gives $5/unit vs x₂ at $4/unit. We pick the x₁-edge.

The Ratio Test: Choosing the Leaving Variable

How far can we increase x₁ before a basic variable hits zero?


s₁ = 100 − 2x₁ ≥ 0  →  x₁ ≤ 100/2 = 50
s₂ =  80 −  x₁ ≥ 0  →  x₁ ≤  80/1 = 80

Minimum ratio: min(50, 80) = 50.

s₁ hits zero first → s₁ leaves the basis.

Wood constraint binds first. We move 50 units along the x₁-axis.

New vertex: (50, 0) with s₁=0, s₂=30.

Summary: One Pivot Algebraically

Before Pivot (Origin)

  • Basic: s₁, s₂
  • Non-basic: x₁, x₂
  • Solution: (0, 0, 100, 80)
  • z = 0
  • Reduced costs: x₁=5, x₂=4

After Pivot (Wood Intercept)

  • Basic: x₁, s₂
  • Non-basic: x₂, s₁
  • Solution: (50, 0, 0, 30)
  • z = 250
  • New reduced costs: ?

Entering: most positive reduced cost (x₁)

Leaving: minimum ratio test (s₁)

We moved along the wood-constraint edge from (0,0) to (50,0).

But we're not done yet. The new reduced costs will tell us whether to continue.

From Geometry to Algebra

Chapter 2 showed us the geometric truth: optimal solutions live at vertices.

We move from vertex to vertex along edges, improving the objective each step.

But how do we actually compute the next vertex without plotting?

We need a systematic algebraic mechanism that:

  • Tracks which variables are basic (vertex coordinates)
  • Tells us which edge to follow (entering variable)
  • Tells us how far we can go (leaving variable)
  • Updates everything in one structured operation

That mechanism is the Simplex Tableau.

Anatomy of the Simplex Tableau

The tableau is an augmented matrix organizing all constraints and the objective.

  • Columns: every variable (decision + slack) + RHS
  • Basis column: which variable currently owns each row
  • Constraint rows: one per basic variable, expressing it in terms of non-basics
  • Objective row (z-row): reduced costs — the marginal value of each non-basic

The tableau encodes a complete basic feasible solution at a glance.

Value = RHS of their row

s₁ = 100
s₂ = 80

Non-Basic Variables

Value = 0 (not in basis)

x₁ = 0

This corresponds to the origin vertex (0,0) — 0 tables, 0 chairs, all resources unused.

Reading the Tableau: Reduced Costs

The z-row coefficients (excluding RHS) are reduced costs.


| Basis | x₁ | x₂ | s₁ | s₂ | RHS |
|-------|----|----|----|----|-----|
| z     | -5 | -4 |  0 |  0 |   0 |
        ↑    ↑
    reduced  reduced
    cost     cost
  • Reduced cost of xⱼ = rate of change in objective per unit increase in xⱼ
  • For maximization with this sign convention: negative = improving
  • x₁: -5 → each table adds $5 profit (uses 2 labor, 1 wood)
  • x₂: -4 → each chair adds $4 profit (uses 1 labor, 2 wood)
  • s₁: 0, s₂: 0 → slack variables don't directly affect profit

Most negative = steepest ascent = best entering candidate.

Pivot Operation: Row Operations

Moving to an adjacent vertex = elementary row operations on the tableau.

Step 1: Choose entering variable — most negative reduced cost → x₁ (-5)

Step 2: Choose leaving variable — minimum ratio test:


s₁ row: 100 / 2 = 50
s₂ row:  80 / 1 = 80  → minimum = 50, so s₁ leaves

Pivot element = 2 (intersection of x₁ column, s₁ row)

Step 3: Normalize pivot row — divide row by pivot element:


New x₁ row = Old s₁ row ÷ 2
          = [1, 0.5, 0.5, 0 | 50]

Step 4: Eliminate x₁ from other rows — add multiples of new pivot row:

  • s₂ row: Old s₂ row − 1 × New x₁ row
  • z row: Old z row + 5 × New x₁ row

After First Pivot: New Tableau


| Basis | x₁ | x₂  | s₁  | s₂ | RHS |
|-------|----|-----|-----|----|-----|
| x₁    |  1 | 0.5 | 0.5 |  0 |  50 |
| s₂    |  0 | 1.5 | -0.5|  1 |  30 |
| z     |  0 | -1.5| 2.5 |  0 | 250 |
  • Basis updated: [x₁, s₂] — x₁ entered, s₁ left
  • x₁ row: normalized pivot row — x₁ expressed in terms of non-basics (x₂, s₁)
  • s₂ row: x₁ eliminated — s₂ expressed in terms of non-basics
  • z row: x₁ eliminated — reduced costs updated
  • Identity columns: x₁ column = [1, 0, 0]ᵀ, s₂ column = [0, 1, 0]ᵀ

Interpreting the New Tableau

Current Solution

x₁ = 50 (tables)
s₂ = 30 (unused wood)
x₂ = 0 (chairs)
s₁ = 0 (labor fully used)

Objective Value

$250

RHS of z-row

Reduced costs (z-row):

  • x₂: -1.5 → still negative → can improve further
  • s₁: 2.5 → positive → increasing unused labor would decrease profit
  • s₁'s reduced cost = 2.5 is the shadow price of labor!

Second Pivot: x₂ Enters, s₂ Leaves

Entering: x₂ (reduced cost = -1.5, most negative)

Ratio test for leaving variable:


x₁ row: 50 / 0.5 = 100
s₂ row: 30 / 1.5 = 20  ← minimum

s₂ leaves. Pivot element = 1.5 (x₂ column, s₂ row)

Row operations:

  1. Normalize pivot row: New x₂ row = Old s₂ row ÷ 1.5
  2. Eliminate x₂ from x₁ row: New x₁ row = Old x₁ row − 0.5 × New x₂ row
  3. Eliminate x₂ from z row: New z row = Old z row + 1.5 × New x₂ row

Optimal Tableau Reached


| Basis | x₁ | x₂ | s₁    | s₂    | RHS |
|-------|----|----|-------|-------|-----|
| x₁    |  1 |  0 |  2/3  | -1/3  |  40 |
| x₂    |  0 |  1 | -1/3  |  2/3  |  20 |
| z     |  0 |  0 | 10/3  |  5/3  | 280 |
  • Basis = [x₁, x₂] — both decision variables basic
  • Solution: x₁ = 40 tables, x₂ = 20 chairs
  • Slacks: s₁ = 0, s₂ = 0 — both constraints binding
  • Profit = $280 (maximum)
  • All reduced costs ≥ 0 → optimality condition satisfied
  • Shadow prices: labor = 10/3 ≈ $3.33, wood = 5/3 ≈ $1.67

Why the Pivot Rules Work

Entering: steepest ascent edge

Leaving: first constraint hit

Together: move to adjacent vertex with better objective.

Geometric interpretation:

  • Each basis = a vertex (intersection of n constraint boundaries)
  • Pivot = slide along edge where one constraint becomes slack, another becomes tight
  • Ratio test = distance to next vertex along that edge
  • Reduced cost = directional derivative along that edge

The Tableau Is a Vertex Machine

Each tableau = one vertex of the feasible region.

Each pivot = one edge traversal to a better vertex.

The z-row = compass telling us which edge improves the objective.

The ratio test = odometer telling us how far we can go.

But what if the compass breaks? What if no edge improves things — yet we're not optimal?

What Could Go Wrong?

We assumed:

  • Every pivot makes strict progress (objective increases)
  • Ratio test always has a unique minimum
  • We never return to a previous vertex

What if the reduced cost is negative but the ratio test fails?

What if multiple rows tie for the minimum ratio?

What if we cycle forever without reaching optimality?

  • Maximum profit: z = $280
  • Slack variables: s₁ = 0, s₂ = 0

The basis {x₁, x₂} tells us which constraints are active at the optimal vertex.

Sensitivity: Range of Validity

  
Shadow prices hold only while the optimal basis remains unchanged.

  
We compute allowable changes to RHS before a basic variable hits zero:

  

For wood (s₁ column in basis):
  x₁: 40 - (2/3)Δ ≥ 0  →  Δ ≤ 60
  x₂: 20 - (-1/3)Δ ≥ 0 →  Δ ≥ -60
  Wood range: [100-60, 100+60] = [40, 160]  ❌

Wait — let's recompute carefully using the tableau columns...
  

  
Correct calculation using the inverse basis matrix (the slack columns in the optimal tableau):

  

Current RHS: [40, 20]ᵀ
Slack columns (B⁻¹):
  s₁: [2/3, -1/3]ᵀ
  s₂: [-1/3, 2/3]ᵀ

Wood (b₁ = 100):  40 - (2/3)Δ₁ ≥ 0  →  Δ₁ ≤ 60
                  20 - (-1/3)Δ₁ ≥ 0 →  Δ₁ ≥ -60
  Allowable: Δ₁ ∈ [-60, 60]  →  Wood ∈ [40, 160]

Labor (b₂ = 80):  40 - (-1/3)Δ₂ ≥ 0 →  Δ₂ ≥ -120
                  20 - (2/3)Δ₂ ≥ 0  →  Δ₂ ≤ 30
  Allowable: Δ₂ ∈ [-120, 30]  →  Labor ∈ [-40, 110] → [0, 110] (non-negativity)
  

  
Valid ranges: Wood ∈ [40, 160], Labor ∈ [0, 110]

  
Beyond these, the basis changes → shadow prices change.

Unboundedness Detection

  
What if the ratio test fails completely?

  

Maximize: x₁ + x₂
s.t. x₁ - x₂ ≤ 10
     -x₁ + x₂ ≤ 5
     x₁, x₂ ≥ 0
  

  
Initial tableau (after adding slacks):

  

| Basis | x₁ | x₂ | s₁ | s₂ | RHS |
|-------|----|----|----|----|-----|
| s₁    | 1  | -1 | 1  | 0  | 10  |
| s₂    | -1 | 1  | 0  | 1  | 5   |
|-------|----|----|----|----|-----|
| z     | -1 | -1 | 0  | 0  | 0   |
  

  
Enter x₁ (most negative reduced cost). Column: [1, -1]ᵀ

  
Ratio test: Only positive entries in pivot column qualify.

  
Row 1: 10/1 = 10. Row 2: -1 ≤ 0 → ineligible.

  
Only one ratio → x₁ enters, s₁ leaves. But what if no positive entries?






  
Unboundedness: Geometric View

  

| Basis | x₁ | x₂ | s₁ | s₂ | RHS |
|-------|----|----|----|----|-----|
| s₁    | 1  | -1 | 1  | 0  | 10  |
| s₂    | -1 | 1  | 0  | 1  | 5   |
|-------|----|----|----|----|-----|
| z     | -1 | -1 | 0  | 0  | 0   |
  

  
Suppose we enter x₂ instead. Column: [-1, 1]ᵀ

  
Row 1: -1 ≤ 0 (ineligible). Row 2: 5/1 = 5.

  
Now suppose a different problem where entering column has all entries ≤ 0:

  

Maximize: x₁ + x₂
s.t. -x₁ + x₂ ≤ 5
      x₁, x₂ ≥ 0
  

  
Tableau: x₂ column = [1]ᵀ (positive) — bounded.

  
But if constraint were: -x₁ - x₂ ≤ -5 (i.e., x₁ + x₂ ≥ 5)...

  
Then entering column for x₁ could be all ≤ 0 → unbounded.

  
Geometric meaning: Feasible region open in improving direction. No vertex maximizes.






  
Infeasibility and Phase I

  
What if no obvious initial BFS exists?

  
Example: ≥ constraints or = constraints

  

Minimize: 3x₁ + 2x₂
s.t. 2x₁ + x₂ ≥ 100
      x₁ + 2x₂ ≥ 80
      x₁, x₂ ≥ 0
  

  
Adding slack gives: 2x₁ + x₂ - s₁ = 100. Setting x=0 → s₁ = -100 (infeasible)

  
Phase I (Two-Phase Method):

  
    
    
  1. Add artificial variables a₁, a₂ ≥ 0
    2. 
    
  2. Minimize a₁ + a₂ (sum of artificials)
    3. 
    
  3. If min > 0 → original problem infeasible
    4. 
    
  4. If min = 0 → drop artificials, proceed to Phase II with feasible basis
    5. 
  

  
Big-M Method alternative: Penalize artificials in objective with huge M.

  
Modern solvers use dual simplex or interior point — Phase I mostly pedagogical.

Core Insight Restated

  
The simplex tableau is organized Gaussian elimination.

  
It maintains an invertible basis matrix B implicitly.

  
Each pivot = one Gauss-Jordan step swapping a column of B with a non-basic column.

  
The tableau is B^{-1}A \mid B^{-1}b with the objective row c_B^T B^{-1}A - c^T.

  
Geometry (vertices, edges) = Algebra (basis, pivots).

  
You now see both sides simultaneously.






  
Limitations of the Simplex Method

  
    
    
  • Worst-case complexity: Exponential (Klee-Minty cube, 1972). A cleverly constructed n-variable LP forces 2^n - 1 pivots.
    • 
    
  • Practical reality: Remarkably efficient on real-world problems — typically 2m \text{ to } 3m pivots for m constraints.
    • 
    
  • Large sparse problems: Full tableau stores O(mn) dense entries — wasteful when A is sparse.
    • 
    
  • Modern solvers use:
      
      
        
    • Revised simplex (maintain B^{-1} or LU factors only)
      • 
        
    • Interior point methods (polynomial complexity, different geometry)
      • 
      
    
    
    • 
  

  
The tableau is a teaching lens, not always the computational engine.






  
Duality: The Shadow Price Connection

  
Primal (our running example):

  

max  5x₁ + 4x₂
s.t. 2x₁ +  x₂ ≤ 100
      x₁ + 2x₂ ≤  80
      x₁, x₂ ≥ 0
  

  
Dual:

  

min 100y₁ + 80y₂
s.t. 2y₁ +  y₂ ≥ 5
      y₁ + 2y₂ ≥ 4
      y₁, y₂ ≥ 0
  

  
Optimal dual: y_1 = 10/3, \; y_2 = 5/3 — exactly the shadow prices from the tableau's objective row.

  
Strong duality: 5(40) + 4(20) = 280 = 100(10/3) + 80(5/3).

  
Complementary slackness: x_1>0 \Rightarrow 2y_1+y_2=5, x_2>0 \Rightarrow y_1+2y_2=4, s_1=s_2=0 \Rightarrow y_1,y_2>0.

What Comes Next: Revised Simplex

  
The full tableau stores redundant information — every column of A transformed by B^{-1}.

  
Revised simplex maintains only:

  
    
    
  • The basis inverse B^{-1} (or LU factorization)
    • 
    
  • The basic variable values x_B = B^{-1}b
    • 
    
  • The basic cost vector c_B
    • 
  

  
Pricing step computes reduced costs on demand:

  

π = c_B^T B^{-1}          (simplex multipliers = shadow prices)
r_j = c_j - π A_j         (reduced cost for non-basic j)
  

  
Only the entering column B^{-1}A_j is computed when needed.

  
Standard in commercial solvers (CPLEX, Gurobi, Xpress) — exploits sparsity, enables reinversion control.






  
What Comes Next: Interior Point Methods

  
Simplex walks the boundary (vertices → edges → vertices).

  
Interior point methods stay strictly inside the feasible region.

  
Barrier method: Add logarithmic barrier -\mu \sum \ln(x_i) to objective, solve sequence of unconstrained problems as \mu \to 0.

  
Follows the central path — a smooth curve through the interior converging to optimum.

  
Complexity: Polynomial (O(\sqrt{n} L) iterations, L = input bit length).

  
Trade-off: Each iteration solves a linear system (Newton step) — expensive but fewer iterations for very large problems.

  
Modern solvers run both and choose automatically.
