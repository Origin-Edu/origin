Central Question

How do we maximize weekly profit when every product consumes limited resources?

Running Example: A furniture workshop produces tables and chairs.

Profit per unit: Tables = $90 | Chairs = $50

Three weekly resource limits:

  • Labor: 100 hours
  • Machine time: 80 hours
  • Wood: 120 board-feet

Beginner's Confusion: Why Not All Tables?

The naive plan: make only tables — the higher-profit item.

Labor per table: 2 hours → Max tables = 100 ÷ 2 = 50 tables

Machine per table: 1 hour → 50 tables uses 50 hours (limit 80) ✓

Wood per table: 3 board-feet → 50 tables uses 150 board-feet (limit 120) ✗

Infeasible. Wood constraint violated.

Profit would have been 50 × $90 = $4,500 — but we can't build it.

Chapter 2: Building the Model

From word problem to mathematical structure

The Workshop Problem — Recall the Numbers

Chapter 1 gave us a concrete situation:

  • Resources per week: 100 labor hours, 80 machine hours, 120 wood units
  • Tables: 2 labor, 1 machine, 3 wood → $90 profit
  • Chairs: 1 labor, 2 machine, 2 wood → $50 profit
  • Question: How many tables and chairs to maximize weekly profit?

We solved this by trial and error. Now we build a general method.

Decision Variables: What We Control

We name the unknown quantities we get to choose:

x₁ = number of tables produced per week
x₂ = number of chairs produced per week

Non-negativity: x₁ ≥ 0, x₂ ≥ 0

We cannot produce negative furniture. This is not a modeling choice — it's physical reality.

Convention: Green = decision variables (what we maximize over)

Objective Function: What We Maximize

Total weekly profit = (profit per table) × (tables) + (profit per chair) × (chairs)

Maximize Z = 90x₁ + 50x₂
  • 90 = unit profit per table ($)
  • 50 = unit profit per chair ($)
  • Z = total profit ($/week)

Convention: Orange = objective function (what we optimize)

Constraints: The Resource Limits

Each resource gives one inequality. Left side = usage, right side = availability.

Labor:   2x₁ + 1x₂ ≤ 100
Machine: 1x₁ + 2x₂ ≤ 80
Wood:   3x₁ + 2x₂ ≤ 120

Coefficients come directly from the resource requirements per unit.

Convention: Blue = constraints (limits we must respect)

Standard Form: The Canonical LP Structure

Every linear program can be written as:

Maximize cᵀx   subject to   Ax ≤ b,   x ≥ 0

Mapping our workshop:


c = [90, 50]                    # objective coefficients (orange)
A = [[2, 1],                    # labor coefficients
     [1, 2],                    # machine coefficients
     [3, 2]]                    # wood coefficients
b = [100, 80, 120]              # resource limits (blue)
x = [x₁, x₂]                    # decision variables (green)

Feasible Region

The set of all valid production plans

Green = feasible   |   Red = infeasible

Graphing the Constraints: Line by Line

Each inequality Ax ≤ b defines a half-plane. The boundary line is Ax = b.

Labor: 2x₁ + x₂ = 100
Intercepts: (50, 0), (0, 100)
Machine: x₁ + 2x₂ = 80
Intercepts: (80, 0), (0, 40)
Wood: 3x₁ + 2x₂ = 120
Intercepts: (40, 0), (0, 60)

Test point (0,0): 0 ≤ limit ✓ → origin side is feasible for all three.

The Feasible Polygon Emerges

Intersection of all half-planes + non-negativity = convex polygon

Vertices (corner points):
  • (0, 0) — origin
  • (0, 40) — machine & y-axis
  • (20, 30) — labor ∩ machine
  • (40, 0) — wood & x-axis
  • (33.3, 0) — labor & x-axis

× (50, 0) — violates wood: 3(50) + 2(0) = 150 > 120

The feasible region is bounded and convex.

Corner Points: Candidates for Optimality

Why only check vertices?

  • The objective Z = 90x₁ + 50x₂ is a linear function
  • Its level sets are parallel lines: 90x₁ + 50x₂ = constant
  • Moving the level line in the improving direction (increasing Z)
  • The last feasible point touched is always a vertex
  • Interior points can never be optimal — you can always slide further

This is the Fundamental Theorem of Linear Programming.

We Found the Optimum by Enumeration

But what if there are 100 variables and 200 constraints?

We cannot graph. We cannot list vertices.

We need an algorithm that navigates corners systematically.

Chapter 2 ended with a problem:

Enumerating corners doesn't scale

In 2D: 3 constraints → 3 corners. Easy.

In 100D: 200 constraints → billions of corners.

We need a method that walks from corner to improving corner.

The Simplex Algorithm: a systematic walk along edges.

Slack Variables: Turning Inequalities to Equations

Our furniture factory constraints:


Wood:     2x₁ +  x₂ ≤ 100
Labor:     x₁ + 2x₂ ≤  80
Machine:  3x₁ + 2x₂ ≤ 120
x₁, x₂ ≥ 0

Add slack variables s₁, s₂, s₃ ≥ 0 (unused resources):


2x₁ +  x₂ + s₁ = 100
 x₁ + 2x₂ + s₂ =  80
3x₁ + 2x₂ + s₃ = 120

s₁ = unused wood, s₂ = unused labor, s₃ = unused machine time.

Now we have 3 equations, 5 variables. Infinite solutions — but corners are special.

Basic Feasible Solutions: Algebraic Corners

Rule: Set n variables to zero (nonbasic), solve for m basic variables.

Here: 5 variables, 3 equations → set 2 to zero, solve for 3.

Example: Origin (0,0)

Set x₁=0, x₂=0 (nonbasic). Solve:


s₁ = 100
s₂ =  80
s₃ = 120

Basic vars: s₁, s₂, s₃ | Nonbasic: x₁, x₂

Profit Z = 90(0) + 50(0) = $0

Each BFS = One Vertex

  • (0,0) → basic: s₁,s₂,s₃
  • (40,0) → basic: x₁,s₁,s₂
  • (20,30) → basic: x₁,x₂,s₃
  • (0,40) → basic: x₂,s₁,s₃

The Simplex Tableau: Organizing the Search

Initial tableau for Max Z = 90x₁ + 50x₂:


       x₁   x₂   s₁   s₂   s₃  | RHS
Z     -90  -50   0    0    0  |   0
s₁      2    1    1    0    0  | 100
s₂      1    2    0    1    0  |  80
s₃      3    2    0    0    1  | 120

Key Components

  • Z-row (reduced costs): Negative = can improve by entering
  • Constraint rows: Current basic variable values (RHS)
  • Basis: s₁, s₂, s₃ (identity matrix columns)

Step 1: Choose Entering Variable

Most negative reduced cost: x₁ (-90) → enters basis

Step 2: Choose Leaving Variable (Min Ratio Test)


s₁: 100/2 = 50
s₂:  80/1 = 80
s₃: 120/3 = 40  ← MINIMUM → s₃ leaves

Pivot Step: Walking to a Better Corner

Pivot on row s₃, column x₁ (value 3). Row operations:

New x₁ row (divide by 3):


x₁:  1   2/3   0    0   1/3  |  40

Update Z-row: Z + 90 × new_x₁_row


Z:   0   10    0    0   30   | 3600

Update s₁ row: s₁ - 2 × new_x₁_row


s₁:  0  -1/3   1    0  -2/3  |  20

Update s₂ row: s₂ - 1 × new_x₁_row


s₂:  0   4/3   0    1  -1/3  |  40

New BFS: x₁=40, x₂=0, s₁=20, s₂=40, s₃=0

Vertex (40,0) | Profit $3,600 | Wood: 80/100, Labor: 40/80, Machine: 120/120 ✓

Checking for a Second Pivot: Are We Optimal?


       x₁   x₂   s₁   s₂   s₃  | RHS
Z      0   10    0    0   30  | 3600
x₁     1   2/3   0    0   1/3 |  40
s₁     0  -1/3   1    0  -2/3 |  20
s₂     0   4/3   0    1  -1/3 |  40

Reduced costs for nonbasic variables (x₂, s₃):

  • x₂: +10
  • s₃: +30

Both are positive. For maximization, positive reduced cost means decreasing Z if entered.

No improving direction exists. We are optimal.

Simplex terminates after one pivot: (0,0) → (40,0) | Z* = $3,600

Why not (20,30)? Z = $3,300 — worse than (40,0).

Simplex never visits (20,30) because the edge from (40,0) goes downhill.

Optimality Condition: No Improving Direction

For Maximization

At optimal BFS, all reduced costs ≥ 0.

No nonbasic variable can enter to increase Z.

Geometric meaning: Every edge from this vertex goes downhill or flat.

For Minimization

At optimal BFS, all reduced costs ≤ 0.

No nonbasic variable can enter to decrease Z.

Why This Works

  • Feasible region is a convex polyhedron
  • Objective is linear → optimum at a vertex
  • Simplex walks edges, strictly improving Z each step
  • Finite vertices → finite steps → guaranteed termination

Decision: Should We Buy More Wood at $25/unit?

Analysis

Shadow price of wood = $30/unit

Offer price = $25/unit

Net gain = $30 − $25 = $5/unit

Allowable increase = 40 units

Decision

YES — buy up to 40 units

Extra profit = 40 × $5 = $200

New total profit = $3,600 + $200 = $3,800

New wood RHS = 160 (at limit of validity)

Rule: Buy a resource if its market price < shadow price, up to the allowable increase.

Decision scenario using the running example. Wood shadow price $30, offer $25, allowable increase 40 units. Clear yes decision with calculated profit impact.

Decision: Overtime Labor at $20/hr?

Analysis

Shadow price of labor = $15/hr

Overtime cost = $20/hr

Net loss = $15 − $20 = −$5/hr

Reduced Cost:
The Price to Force a Product In

At optimum (40, 0), chairs (x₂) = 0. Why?

Reduced Cost of Chairs = −$20

Each chair forced into the solution reduces profit by $20

...unless its profit coefficient rises by $20 (to $70)

...or constraints change to make chairs more attractive

Reduced cost = opportunity cost of producing one unit of a nonbasic variable.

  • Basic variables (tables): reduced cost = 0
  • Nonbasic at lower bound (chairs): reduced cost ≤ 0 for max problem
  • Magnitude = profit increase needed to make it enter basis

The Vertex Theorem

If an optimal solution exists, at least one lives at a vertex.

Simplex doesn't search the interior. It walks the edges — vertex to adjacent vertex — improving profit each step.

Our workshop: (0,0) → (0,30) → (20,30) → (40,0)

4 vertices visited. 3 pivots. Done.

Where LP Breaks Down

1. Linearity

No economies of scale. 100th table costs same as 1st.

2. Certainty

Demand, prices, machine hours known exactly. No stochasticity.

3. Divisibility

Fractional tables? x₁ = 40.5 makes no physical sense.

4. Single Objective

Profit only. No tradeoffs: quality vs speed, risk vs return.

Our solution (40, 0) happens to be integer — lucky! Usually it's not.

Duality: The Shadow Problem

Primal (Our Workshop)

Maximize 90x₁ + 50x₂

subject to:


2x₁ +  x₂ ≤ 80   (large lathe)
 x₁ + 2x₂ ≤ 60   (small lathe)
 x₁ +  x₂ ≤ 50   (assembler)
 x₁ + 2x₂ ≤ 80   (finisher)
x₁, x₂ ≥ 0

Optimal: $3,600

Dual (Resource Buyer)

Minimize 80y₁ + 60y₂ + 50y₃ + 80y₄

subject to:


2y₁ + y₂ + y₃ + y₄ ≥ 90   (table value)
 y₁ + 2y₂ + y₃ + 2y₄ ≥ 50  (chair value)
y₁, y₂, y₃, y₄ ≥ 0

Optimal: $3,600

Weak Duality: Any feasible dual ≥ any feasible primal.

Strong Duality: At optimum, they are equal.

Dual variables y₁...y₄ = shadow prices from Chapter 4.
