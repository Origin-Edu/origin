Corner Point Theorem: Why Only Vertices Matter

  • Feasible region = convex polyhedron (intersection of half-spaces)
  • Objective = linear function (plane in 3D, line in 2D)
  • A linear function on a convex set attains its max/min at an extreme point (vertex)
  • If multiple optima exist → entire edge (or face) is optimal
Our factory: 5 vertices → only 5 candidates to check.
(0,0), (0,40), (15,25), (30,0), (37.5,0) — but (37.5,0) violates labor.

Simplex exploits this: search only vertices, not interior.

Simplex Intuition: Walk the Edges Uphill

The Walk

  1. Start at origin (0,0) — easy feasible point
  2. Move along edge to adjacent vertex with higher Z
  3. Repeat: each step = one pivot
  4. Stop when no improving edge exists

Why It Finishes

  • Finite vertices (combinatorial bound)
  • Strictly increasing Z each pivot
  • No cycles with Bland's rule
  • Typical: O(m) pivots for m constraints
(0,0) → (0,40) → (15,25) → (30,0)
Our factory's simplex path (4 vertices, 3 pivots)

  3. Pivot element: Row s₂, Col x₁ = 4
  4. Row ops: Normalize pivot row, eliminate x₁ from other rows

Reduced Costs: The Compass Needle

For non-basic variable \(x_j\):

\(\bar{c}_j = c_j - \mathbf{c}_B^T B^{-1} A_j = c_j - z_j\)

  • \(\bar{c}_j > 0\) → bringing \(x_j\) into basis improves Z
  • \(\bar{c}_j < 0\) → bringing \(x_j\) in worsens Z (for max)
  • \(\bar{c}_j = 0\) → alternative optimum on that edge
  • Optimality: All \(\bar{c}_j \le 0\) (max) → stop
Our example, initial tableau:
\(\bar{c}_1 = 90 - 0 = 90\) (entering candidate)
\(\bar{c}_2 = 50 - 0 = 50\)
x₁ enters first — higher marginal profit per unit.

Sensitivity Report: The "What If" Machine

Every LP solver produces a sensitivity report. Here's what ours says for wood:

Resource    | Shadow Price | Allowable Increase | Allowable Decrease
------------|--------------|-------------------|-------------------
Wood        | $10/board-ft | 60 board-ft       | 40 board-ft
Labor       | $0/hour      | ∞                 | 10 hours
Storage     | $20/unit     | 10 units          | 15 units
  • Shadow price = marginal value of one more unit of resource (while basis stays same)
  • Allowable range = how much RHS can change before the optimal vertex changes (basis shifts)
  • Labor shadow price = $0 because we already have 10 hours slack — extra labor is worthless at the margin

Key insight: Shadow prices are only valid within the allowable range. Beyond that, the optimal basis changes and shadow prices jump.

The Dual Problem: The Resource Buyer's View

Every LP (primal) has a dual. For our factory:

Primal (Factory Owner — Maximize Profit)
max 90x₁ + 50x₂
s.t. 8x₁ + 3x₂ ≤ 300 (wood)
    4x₁ + 2x₂ ≤ 120 (labor)
    1x₁ + 1x₂ ≤ 40 (storage)
    x₁, x₂ ≥ 0
Dual (Resource Buyer — Minimize Cost)
min 300y₁ + 120y₂ + 40y₃
s.t. 8y₁ + 4y₂ + 1y₃ ≥ 90 (table's resource value ≥ price)
    3y₁ + 2y₂ + 1y₃ ≥ 50 (chair's resource value ≥ price)
    y₁, y₂, y₃ ≥ 0
  • y₁, y₂, y₃ = shadow prices (imputed value per unit of wood, labor, storage)
  • Dual constraints: resources used by a product must be worth at least its selling price
  • Strong Duality Theorem: If primal has optimal solution, dual does too, and max profit = min cost

New Product: Should We Add Sofas?

Marketing proposes a sofa: $150 profit, uses 12 wood, 6 labor, 2 storage.

We don't need to re-solve the whole LP. Use reduced cost (pricing out):

Reduced cost = Price − (Resource usage × Shadow prices)
= 150 − (12 × y₁ + 6 × y₂ + 2 × y₃)
= 150 − (12 × 5 + 6 × 10 + 2 × 0)
= 150 − (60 + 60 + 0)
= 150 − 120 = $30
Reduced cost = $30 > 0 → Sofa is profitable at current shadow prices!
It should enter the basis. The optimal product mix will change.

The Integer Reality: 15.5 Tables Don't Exist

Our LP optimum (15, 25) happened to be integer — lucky coincidence.

Change profits: Tables $95, Chairs $50.

LP relaxation now gives (18.75, 12.5) — profit $2,406.25.

You cannot build 18.75 tables. Fractional solutions are infeasible in reality.

Integer Programming (MILP) is NP-hard. No polynomial-time algorithm exists (unless P=NP).

Limitations of Linear Programming

Linearity

  • Constant returns to scale
  • No synergies or interactions
  • Marginal profit constant

Certainty

  • All parameters known exactly
  • No demand uncertainty
  • No supply disruptions

Divisibility

  • Fractional decisions allowed
  • Fails for discrete goods
  • Requires MILP for integers

Single Objective

  • One metric to optimize
  • No trade-off exploration
  • Multi-objective needs Pareto

Static (Single Period)

  • No inventory carryover
  • No learning curves
  • Multi-period → dynamic programming or multi-stage stochastic LP

What Comes Next: Extensions That Keep the Core

Quadratic Programming

Portfolio optimization: minimize xᵀΣx subject to return target. Convex QP — still polynomial.

Stochastic LP

Uncertain demand → scenarios with probabilities. Two-stage: decide now, recourse later. Explodes in size.

Multi-Objective

Profit vs. carbon vs. labor. No single optimum — Pareto frontier. Weighted sum or ε-constraint.

Column Generation

Huge LPs (crew scheduling). Generate variables on demand via pricing problem. Dual values guide search.

Benders Decomposition

Complicating variables (e.g., facility location). Master problem chooses y, subproblem checks feasibility/optimality. Cuts added iteratively.
